How this works

Three kinds of "size"

Total parameters set the memory you need to hold the weights. Active parameters (mixture-of-experts) set how much is read per token, so they set decode speed. Lookup parameters (n-gram and per-layer embedding tables, as in Qwen3.8-Flash-Next, LongCat and Gemma 4 E-series) are table lookups: they take memory but almost no bandwidth, so they can sit in system RAM or on SSD. The main chart lets you switch between total and active; the guide below uses all three.

Fit and speed estimate

Weights are placed in VRAM first, then system RAM, then (if allowed) SSD. For a MoE, 30% of active parameters are assumed to be always-read (attention, shared experts) and are placed first; routed experts fill what is left, and their reads are spread evenly across wherever they live. Decode speed is 55% of peak bandwidth divided by bytes read per token, summed over tiers. This is a roofline ceiling for single-stream decoding: it ignores prompt processing, KV-cache growth, multi-GPU communication and kernel quality, and real numbers are usually lower. Use it to separate comfortable from painful, not as a benchmark. GPU bandwidths are representative values for the cards in each series and VRAM slot, system RAM is assumed ~80 GB/s (desktop) or ~200 GB/s (192 GB and up), and unified-memory classes are ~120 / 270 / 600 GB/s. All are approximate and live in assets/hardware.js.

Quantization and NVFP4

Footprints use effective bits per weight: 8-bit 8.5, 4-bit 4.85 (GGUF Q4_K_M) or 4.5 (NVFP4: 4-bit floats with an 8-bit scale per 16 weights), 3-bit 3.9. RTX 5000 and Blackwell workstation cards have native FP4 tensor cores, so "4-bit" resolves to NVFP4 there; older cards use GGUF-style 4-bit. A model already released at a lower precision is never inflated. Decode is bandwidth-bound, so the main benefit of NVFP4 hardware is quality per bit and faster prompt processing, not much faster decoding. The Intelligence Index was measured on providers' hosted (typically near-native) endpoints; quantized local copies will score somewhat lower, especially below 4 bits on small models.

The quadrant

Horizontal: relative percentile on coding and agentic evaluations (Terminal-Bench, τ²-bench, SciCode, APEX-Agents, …) minus percentile on knowledge and instruction-following evaluations (Omniscience, IFBench, AA-LCR, GPQA, HLE). Artificial Analysis publishes no creative-writing or roleplay evaluation, so the left end means "knowledge and chat strength relative to coding", not measured creativity. Vertical: the Intelligence Index against speed, using AA's measured hosted output speed (available for about half of the models) or the estimate for your hardware.

Data

Scores, speed, release dates, parameter counts and the model-picker defaults come from Artificial Analysis pages. Exact totals and stored sizes come from Hugging Face safetensors headers; lookup-table sizes are curated from model cards in data/overrides.json. Where AA and Hugging Face disagree by more than 8% the AA figure is kept and a note appears in the model's tooltip. Missing or wrong? Open an issue or edit the overrides.
